# P2 — recorridos y alternativas accesibles, 17/10/2026

Este lote corrige MED-002 y UX-001 sobre las 134 fichas de la propuesta P1. No autoriza publicación, no incorpora proyectos ni cambia información comercial, imágenes, derechos o destinos externos.

## MED-002

`usable_virtual_tours` interpreta la verificación visual ausente o nula como no acreditada. Una alternativa registrada con `visualVerification: null` sólo se conserva conforme a la política existente, junto con un recorrido utilizable; nunca se convierte en una escena verificada. El dry-run de `scripts/migrate-project-embeds.py` completa los 134 proyectos y comprueba idempotencia sin escribir investigación ni HTML.

La regeneración completa propone 24 diferencias previas entre plantillas y fichas especializadas. No se aplicaron: la corrección UX utiliza una migración distinta y estrecha que conserva las secciones existentes.

## UX-001

Las 132 fichas que contienen visores incluyen ahora un enlace estático adyacente por cada iframe: 132 mapas y 88 recorridos, 220 enlaces. El destino coincide exactamente con su `data-embed-fallback` ya registrado. No cambia ningún atributo del iframe, consulta de dirección, título, permiso, fuente ni lista de hosts. Los enlaces usan HTTPS, `target="_blank"`, `rel="noopener noreferrer"` y un nombre accesible que anuncia la nueva pestaña.

El enlace está presente antes de ejecutar JavaScript y no depende de `load`, `error` ni temporizadores. Ante un error real, el código retira el visor y conserva su alternativa sin duplicarla. La validación del generador y del runtime mantiene la lista permitida; los destinos alterados o no autorizados se rechazan.

Para reproducir la migración sólo de este lote:

```sh
python -B scripts/migrate-embed-alternatives.py
```

El resultado posterior es `projects: 134`, `changed: 0`, `persistentAlternatives: 220`. `--write` sólo inserta alternativas adyacentes: no regenera secciones, precios, identidad ni datos de investigación.
